# WE-260408-43e1 — Sentinel Gate Instance ID Reengineering

## Objective

Fix the `get_instance_id()` function shadowing bug in `sentinel-gate.py` that causes a total write-tool deadlock in VS Code. The local definition (line 160) shadows the imported version from `project_resolver.py` (line 38), resulting in transaction file suffix mismatches that prevent the gate from finding active PREFLIGHT transactions.

## Root Cause

**File:** `~/.claude/plugins/local/empirica-integration/hooks/sentinel-gate.py`

- **Line 38:** `from project_resolver import get_active_project_path, get_instance_id, get_active_session_id`
  - This imports `get_instance_id` from `project_resolver.py`, which has a 5-source priority chain:
    1. `EMPIRICA_INSTANCE_ID` env var
    2. `TMUX_PANE`
    3. `TERM_SESSION_ID` (macOS Terminal.app)
    4. `WINDOWID` (X11)
    5. `None`

- **Line 160:** Local `def get_instance_id()` — shadows the import. Only checks:
    1. `TMUX_PANE`
    2. `tty` subprocess command
    3. `None`

- **In VS Code:** No tmux, no tty → local version returns `None` → gate looks for `active_transaction.json` (no suffix)
- **PREFLIGHT** uses `empirica.utils.session_resolver.get_instance_id()` via the lib version → may return a different suffix
- **Result:** Gate can never find the transaction file PREFLIGHT wrote → all writes blocked → can't even fix the gate
