# Linter writes in check-only mode

## Objective

pyrite lint modifies files while printing CHECK ONLY (read-only)

## Description

Reproduced on 2026-07-30: restore three files to HEAD, confirm a clean tree, run `pyrite lint --scope _work_efforts` with neither --fix nor --dry-run, and the same three files come back dirty with trailing whitespace stripped and EOF newlines added. Root cause: ObsidianLinter has no `fix` attribute at all. The only write guard is `if fixed_content and not self.dry_run` at tools/obsidian-linter/check.py:840, and lint.py forwards --dry-run only when the user passes it. So the default path writes. Affected files this session: WE-251231-ocwm_index.md, WE-251231-tbsw_index.md, TKT-nglm-001_setup_demo_environment.md.
